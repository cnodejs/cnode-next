# admin-list-pagination Specification

## Purpose

定义后台管理列表的统一分页 API 契约、Web 分页控件行为、筛选参数保留规则和适用列表范围，确保管理员能稳定访问完整运营数据。

## Requirements

### Requirement: 后台列表 API 分页契约

后台管理列表 API SHALL 支持页码分页，并返回列表数据和总数信息。

#### Scenario: 请求第一页后台列表

- **WHEN** 管理员请求支持分页的后台列表接口且未提供 `page`
- **THEN** 系统按 `page=1` 处理
- **AND** 响应包含 `data`、`total`、`page`、`limit`

#### Scenario: 请求指定页后台列表

- **WHEN** 管理员请求支持分页的后台列表接口并提供 `page=3&limit=20`
- **THEN** 系统返回第 3 页数据
- **AND** `limit` 为 20
- **AND** `total` 为符合当前筛选条件的总记录数

#### Scenario: 限制过大 limit

- **WHEN** 管理员请求支持分页的后台列表接口并提供超过最大值的 `limit`
- **THEN** 系统使用允许的最大 `limit`
- **AND** 响应中的 `limit` MUST 反映实际使用值

#### Scenario: 空页返回稳定结构

- **WHEN** 管理员请求超出数据范围的页码
- **THEN** 系统返回空 `data` 数组
- **AND** 仍返回正确的 `total`、`page`、`limit`

### Requirement: 后台分页页面体验

后台管理页面 SHALL 使用分页控件访问完整列表，并在翻页时保留当前筛选和搜索条件。

#### Scenario: 后台表格显示分页控件

- **WHEN** 管理员访问支持分页的后台管理页面且总数超过每页数量
- **THEN** 页面显示分页控件
- **AND** 分页控件允许访问上一页、下一页和附近页码

#### Scenario: 翻页保留搜索条件

- **WHEN** 管理员在带搜索条件的后台列表中切换页码
- **THEN** 新页面 URL 保留当前搜索或筛选参数
- **AND** 后台接口按这些条件返回对应页数据

### Requirement: 分页覆盖的后台列表

系统 MUST 为承载完整管理列表的后台接口和页面提供分页，摘要型最近 N 条接口不属于此范围。

#### Scenario: 完整管理列表需要分页

- **WHEN** 后台页面展示话题、用户、审计日志、举报、敏感词、用户封禁或 IP 封禁的完整管理列表
- **THEN** 对应 API 和 Web 页面 MUST 支持分页

#### Scenario: 概览摘要不分页

- **WHEN** 管理员访问后台概览页的统计卡片或最近 N 条摘要模块
- **THEN** 系统可以继续返回固定数量摘要数据
- **AND** 不要求这些摘要接口返回 `total`

### Requirement: 后台分页不受首页轻量分页影响

后台管理列表 SHALL 继续使用数字页码分页，以支持管理员访问完整运营数据；首页 topic feed 的轻量分页模式不得改变后台分页体验。

#### Scenario: 后台保留数字分页

- **WHEN** 管理员访问支持分页的后台管理列表
- **THEN** 分页控件允许访问上一页、下一页和附近页码
- **AND** 不得退化为只显示上一页/下一页。

#### Scenario: 后台翻页保留筛选条件

- **WHEN** 管理员在后台列表中带搜索或筛选条件翻页
- **THEN** 新页面 URL 保留当前搜索或筛选参数
- **AND** 后台接口按这些条件返回对应页数据。
