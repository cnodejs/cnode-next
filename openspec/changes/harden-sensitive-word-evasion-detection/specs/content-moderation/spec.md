# Spec Delta

## MODIFIED Requirements

### Requirement: 敏感词库管理

系统 MUST 维护一个可配置的敏感词库并支持动态更新；所有词条 MUST 使用统一的严格匹配规则，不得因普通语境、词义或插入字符类型提供放行例外。

#### Scenario: 敏感词存储

- **WHEN** 系统启动或运行时
- **THEN** 敏感词库从数据库或配置文件加载
- **AND** 支持管理员通过接口动态增删敏感词

#### Scenario: 敏感词匹配

- **WHEN** 对文本执行敏感词检测
- **THEN** 系统 MUST 支持中英文混合词条，并按本需求定义的归一化和有界插入规则完成匹配
- **AND** 对 10000 字内容的检测 MUST 继续满足敏感词匹配性能要求

#### Scenario: 大小写和兼容字符归一化

- **WHEN** 对文本执行敏感词检测
- **THEN** 系统 MUST 对文本和敏感词执行 Unicode NFKC 兼容归一化和大小写不敏感比较
- **AND** 全角半角或大小写差异 MUST NOT 阻止命中

#### Scenario: 有界插入字符命中

- **WHEN** 文本按顺序包含某个敏感词的全部 Unicode code point
- **AND** 每一对相邻敏感词字符之间插入的字母、数字或汉字不超过 3 个 Unicode code point
- **AND** 每一对相邻敏感词字符之间插入的全部字符不超过 16 个 Unicode code point
- **THEN** 系统 MUST 将该敏感词判定为命中
- **AND** 空白、格式字符、标点、符号和 Emoji MUST 计入 16 个字符的总上限，但 MUST NOT 计入 3 个字母、数字或汉字的上限

#### Scenario: 普通语境不得豁免

- **WHEN** 归一化后的文本命中敏感词
- **THEN** 系统 MUST 报告命中
- **AND** 系统 MUST NOT 因该敏感词在文本中具有普通含义、处于复合词中或存在其他上下文而放行

#### Scenario: 插入字符超过边界

- **WHEN** 某候选匹配的任一对相邻敏感词字符之间插入超过 3 个字母、数字或汉字
- **OR** 插入的全部字符超过 16 个 Unicode code point
- **THEN** 系统 MUST NOT 以该候选位置判定该敏感词命中

#### Scenario: 实时过滤与历史巡检规则一致

- **WHEN** 实时提交路径或历史巡检路径检测相同文本和相同敏感词集合
- **THEN** 两条路径 MUST 产生相同的敏感词命中集合

## ADDED Requirements

### Requirement: 变体命中必须定位原文

系统 MUST 将归一化和有界插入匹配结果定位到原始文本，使巡检结果能够展示包含实际绕过字符的正确原文区域。

#### Scenario: 归一化改变文本长度

- **WHEN** NFKC、大小写转换或 Unicode 字符编码使匹配文本与原文的 code point 或 UTF-16 长度不同
- **AND** 系统发现敏感词命中
- **THEN** 命中的起止位置 MUST 对应参与该次匹配的首个和末个原文字符
- **AND** 巡检预览 MUST 包含该原文命中范围

#### Scenario: 插入字符保留在预览中

- **WHEN** 历史内容通过插入字符命中敏感词
- **THEN** 巡检预览 MUST 保留命中范围内的原始插入字符
- **AND** 预览 MUST NOT 展示归一化或删除字符后的替代文本

### Requirement: 匹配规则变更后的历史重扫

系统 MUST 允许获准管理员使用现有全量巡检能力，按新的敏感词匹配规则重新检查未删除的历史话题和回复；重扫命中继续遵循人工复核流程。

#### Scenario: 发布后执行全量历史重扫

- **WHEN** 新匹配规则发布后管理员创建全量历史巡检任务
- **THEN** 任务 MUST 使用新规则扫描未删除的话题标题、话题内容和回复内容
- **AND** 新发现的命中 MUST 写入现有待复核队列
- **AND** 系统 MUST NOT 因重扫命中而自动删除或隐藏原始内容
