## Context

工作区通过 pnpm catalog 统一 Vite+ 与 Vite alias；API 和 Web 分别使用独立的 Vitest 配置。API 使用 `tsc`，Web 使用 `react-router build`；内部包直接导出源码，没有 `vp pack`、浏览器、覆盖率或基准测试配置。

## Goals / Non-Goals

目标是使用 Vite+ 1.2.0 并保持所有测试、类型检查与构建入口。非目标为业务、UI、数据库及部署调整。

## Decisions

使用目标全局 CLI 运行非交互迁移，保留旧依赖直到迁移器完成原版本识别。不先手工升级依赖，也不使用会修改现有项目设置的 `--full`。

先验证迁移器生成的兼容选项，再逐项尝试删除；只保留通过相同测试集合验证的删除。与直接采用全部新默认值相比，此顺序可定位行为变化。已有用户配置保持不变，覆盖率阈值不放宽。

保留原构建入口和源码导出；不将内部包改为 tsdown，因为这会改变消费者解析方式。应用构建与类型检查验证共享包消费者。

文档按 `cnode-docs` 保留已有权威说明，仅新增本变更的 OpenSpec 契约，避免在长期文档重复依赖清单。

## Risks / Trade-offs

- mock 历史与 DOM 全局行为变化 → 保留断言并运行完整 API、jsdom 测试。
- 新格式化与类型检查诊断 → 仅修复验证需要的具体问题。
- 迁移器存在人工审查项 → 逐条阅读链接并验证相关配置和调用。

## Migration Plan

| 顺序 | 动作                           | 完成条件                    |
| ---- | ------------------------------ | --------------------------- |
| 1    | 保存原版本信息，运行目标迁移器 | BLOCK 已解决，REVIEW 已审查 |
| 2    | 安装并验证兼容配置             | 测试、检查、应用构建通过    |
| 3    | 逐项删除新增兼容选项           | 相同测试集合通过，否则恢复  |
| 4    | 运行组合验证                   | 完整验证通过并报告剩余限制  |

回退时仅还原本变更的依赖、配置和局部修复，再按原锁文件安装；不触及其他工作。
